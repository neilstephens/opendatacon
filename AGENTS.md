# opendatacon — agent guide

## Non-negotiable: comments

Don't write verbose, useless comments. Prefer expressive code over comments;
only comment when the code genuinely needs it. When a comment is needed:

- Be terse.
- Say what the code does — not what it used to do, shouldn't do, or doesn't do.
- Never explain history, past bugs, or rationale that needs context outside
  the code itself.
- Match the comment style already used in the surrounding file/codebase.
